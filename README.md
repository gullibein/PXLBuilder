# PXLBuilder

An AI-native 2D game builder: describe what your game should do, and the AI
changes a structured game model, which then drives the editor and the runtime.

**Current status:** the game world is the interface. Click an object and a
prompt appears next to it; describe the change; the AI turns it into validated,
undoable operations. Press **Play** to run the level. Objects can be connected
("this switch opens this door", "the blue key opens the blue door") and levels
can have rules ("when the player picks up the key, show a message"). Things can
behave on their own. A few common behaviors are ready-made components
(Patrol, Jumper, Shooter, MovingPlatform, Timer, DoubleJump, LedgeGrab), and
for anything else the AI **programs the behavior**: it writes a behavior
script for the object ("charges at the player when it gets close, then rests",
"a jetpack with fuel", "a platform that crumbles", "water the player swims in").
A script can act on other things too, so an area (water, mud, a trampoline)
changes whatever enters it. Scripts are data in a small
event-based language (variables, states, expressions, game actions), checked
before they are applied and readable in the details panel. The camera has
per-level settings (zoom, look-ahead, dead zone, limits, a still camera aimed
at a spot) and effects for rules and scripts (shake, flash, zoom, focus on
something, follow something else).
See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Run

```bash
npm install
cp .env.example .env.local   # then put your Anthropic API key in it
npm run dev                  # http://localhost:5173
```

The key is read only by the dev server (`server/`); it is never sent to the
browser. Without a key everything works except the AI, which reports that it
isn't connected.

**GitHub Pages:** `npm run build` builds for `/PXLBuilder/` (set as `base` in
`vite.config.ts`), so `dist/` can be served at `https://<user>.github.io/PXLBuilder/`;
`npm run preview` serves it at http://localhost:4173/PXLBuilder/. The dev server
stays at the root. Pages has no server, so the AI there works only with a key
entered in ⋯ → AI connection (kept in the browser).

**In the published app (claude.ai):** no key needed. The AI runs on your own
Claude account through claude.ai; you're asked once per visit to allow the
page to use Claude, and requests count toward your plan's usage. (Published
pages can't contact other services, so API keys don't work there.) **Save**
works there too: claude.ai asks you to confirm the download.

**Your own key instead (running locally):** ⋯ → **AI connection** takes your Anthropic API key
and calls Claude straight from the browser (no server needed). The key is
checked first, kept for the session (or remembered in this browser if you
tick the box), and sent only to Anthropic. Requests are billed to your
account. Don't remember a key on a shared computer.

## Check

```bash
npm test             # unit tests (core model)

npm run test:e2e     # builds, serves and drives the editor in headless Chromium
```

## Using it

- **Click something** in your game. A prompt appears next to it. Press Enter (or click the prompt) and describe what you want: "Give the player three hearts."
- **Two objects** (Shift+click the second): one prompt about how they relate ("make this switch open this door"). **More**: one prompt for the group (or drag a box around them).
- **Sprite editor**: select an object and ask "open the sprite editor" (or "I want to edit its running animation myself"), or in its Sprites panel use ✎ to edit a sprite (every object using it updates) and **Draw new sprite** to draw one, as its look or for a situation (while running, jumping…). A tool panel of icons: pencil (P), eraser (E, or the right button; under the tools choose **Pixels** or **Area (fill)**: a click clears the whole area of that color, with a **Tolerance** slider), fill (F, with a **Fill tolerance** slider: 0% fills only the very same color, higher takes in close colors too, 100% everything that touches; both are remembered), color picker (I; or hold **Alt** with any tool, it comes back when you let go) and select (S: drag to select, drag inside to move, arrows nudge, flip, Delete, Ctrl+C/X/V also between frames, Ctrl+A, Esc); a palette you can add to and recolor; frames you can duplicate, add, reorder and delete, with the frame before shown faintly and a playing preview; its own Undo for strokes. A strip at the top lists **all of the object's sprites** (its look, its looks for situations, the others in its list): click one to edit it; what you changed in the one you leave is saved first (one Undo each). **+ New sprite** (top of the editor) starts another sprite for the same object, blank or from the drawing you're on (a walk cycle from the standing picture): give it a name and choose where it's used (its normal look, while running, jumping…, or not yet). Saving is one undoable step. Imported pictures up to 64×64 with up to 62 colors can be edited too. Each palette color has an **Opacity** (5–100%): lower lets what is under it show through (shading laid over a color, glass, shadows); the eraser makes pixels fully clear. **Tint** (the object's Sprite, in the details panel, or ask the AI "use one shaded brick picture for all the colors"): the picture is multiplied by the Sprite color, so a picture drawn in white and grays shows in any color with its shading, and a script that changes the color in play recolors it. One picture for all the colors keeps the game file small.
- **Animated sprites**: a sprite with several frames plays them at its speed, in the game and in the editor. Ask the AI ("give the player a walk cycle while running", "make the coin spin"), draw the frames in the sprite editor, or, in a sprite sheet, type which cells play ("1-4") and how fast. The top-down hero walks with a two-frame cycle each way.
- **Draw sprites**: select something and ask "make this look like spikes" or "draw a red mushroom". The AI draws simple pixel art at the object's proportions (a 64×16 hazard gets 32×8 pixels) and makes it the look of every copy; it's added to the object's Sprites, so you can switch back.
- **Wire a switch**: select a Switch; red circles appear left and right of its frame. Drag one onto another object (a door): the switch now opens it. Click the connection's line to select it and describe what it should do instead: "the switch makes the door disappear", "the switch moves the door three squares upwards". Delete removes a selected connection.
- **Logic** (left panel, the connected-dots button): the level's connections and rules as sentences. Switch rules off, remove things, or describe new logic ("when the player has 3 coins, open the exit"). Existing connections show as arrows on the level. An object's details also list its connections, with a small form to add one.
- **The level**: double-click empty space. "Make gravity 30% weaker."
- **Whole game**: the ✦ button in the top bar (Ctrl+K).
- **Start by choosing the kind of game**: the first visit (and ⋯ → New project) asks *Platformer* or *Top-down*. Top-down games start with objects drawn from above: a hero who looks up, down and sideways as he walks, stone walls, floor tiles that always sit under everything, a wandering slime, a door, floor spikes, a teleporter pad and stairs as the goal (plus coins, keys and a lever). Nothing is locked: mix objects or ask the AI to change the kind of game later.
- **Or just tell the AI what game you want**: type it in the field at the top of that window (e.g. *a Boulder Dash game: dig through dirt, collect diamonds, dodge falling rocks*) and press Enter. The starting points are described to the AI with that first request; it builds the game straight away on the platformer starter when that fits, or first moves the new game to the top-down starter (and then builds it) when that is the better start. Undo steps back through each part.
- **Pushing things**: crates, barrels and boulders get the Pushable component (the starter Crate in platformers, the Barrel in top-down games). Walk into one to shove it; walls and other things stop it. A Pushable can slide freely or move exactly one tile per push (Sokoban puzzles). Ask "a puzzle with barrels to push onto the switches".
- **Mass**: heavier things (Physics Body mass; the player is 1) are knocked back less, pushed more slowly, and at 10 times the pusher's weight not at all. A strength power-up can simply raise the player's mass. The starter Crate weighs 2.
- **Friction** (Physics Body, 0.2 is normal): grip on the ground, from both the thing and the floor it stands on. Something sliding slows down by its friction times the floor's (0 is ice: keeps sliding; 1 stops at once). The player speeds up, stops and turns on the ground by its acceleration times its grip there: its own friction times the floor's, each compared to 0.2 (an icy platform at 0.05: about 4 times slower, sliding; more friction: snappier, at most 4 times). Things in the air keep their speed; patrols and wanderers set their own speed. Ask "make this platform icy" or "make the crates slide on ice".
- **Grid and turn-based games**: ask for them ("make it turn-based: one square per key press"). Hits can knock things back or not (Damage Receiver → knockback; 0 keeps everything on its square), and scripts can see what is on a square (thing_at), so moves, attacks and barrel pushes stay on the grid.
- **Top-down games** (Zelda, Rogue): ask "make it a top-down game". The player then walks in every direction with the arrows or WASD (no jumping) and the level has no gravity, so nothing falls and walls block from every side. Enemies chase in every direction, patrol up and down (Patrol start direction up/down) and shoot the way they face; a top-down player shoots the way it last walked. Sprites can have *up* and *down* looks. The AI builds rooms and corridors instead of jumps, and levels are checked by walking. By hand: Character Controller → movement, and the level's gravity.
- **Show more while editing**: ask any prompt, e.g. on the Player: "show the jump height above the player" or "show how far it can jump" (a panel with values, or the jump arc). Only shown while editing; ⋯ → **Hide info on the level** removes them.
- **Changes land where they belong**: ask on the Player "the player kills mushroom enemies by jumping on them, but other enemies can't be killed that way" and the AI makes the *Mushroom* stompable (every mushroom) instead of changing the player. It says so, the prompt shows "Changed: Mushroom (every copy…)", and the changed objects glow. If what you describe doesn't exist yet, it tells you what to do first.
- **Trash can** (bottom bar, right of Objects): tap it to delete what is selected, or drag objects onto it (it turns red) to delete them; works with a finger as with the mouse. Undo brings them back.
- **Phones**: the Objects panel stays small (about a third of the screen at most): groups are a single row of chips, objects are small tiles, and **Groups** hides the groups altogether (remembered).
- **Touch screens**: two fingers pan the level and pinch to zoom (whatever one finger had started is cancelled, so nothing is drawn between your fingers); one finger taps to select (a placed object is selected even while drawing with an object), drags to move or draw; double-tap empty space for the level prompt.
- **Level variety**: each time you ask for a level, the app picks a layout at random (a tower built in layers, a descent from the top, a hub in the middle with branches, a valley, a mountain, a zig-zag climb, two paths, out-and-back, islands, a shaft, a basement, a long run; for top-down games dungeon rooms, a maze, a ring…), where the player starts and where the goal goes, and tells the AI the shapes of your other levels so it builds something different. Ask for a specific layout and it builds that instead. Routes can turn around and climb back over the floor below, so levels can be built upward in layers.
- **Right-click a placed object**: **Details…**, **Edit sprite** (the sprite editor on its picture), **Code**, **Copy**, **Cut**, **Delete**; on empty space after copying, **Paste here**. Right-clicking an object in **Objects** also offers Edit sprite and Code.
- **Ask AI about a library object or a sound**: right-click an object in **Objects**, or a sound in **Sounds**, → **Ask AI…** opens a prompt card about just that object or sound, just above it: "make this object yellow", "give it a hat", "make it twice as fast"; "I want this sound to be lower in pitch", "make it shorter". A change to an object changes the object itself, so every copy of it in every level; **Make it a new object instead** keeps the old one and adds the changed one to the library. A changed sound stays the same sound (scripts that play it keep playing it) and the card has **▶ Play it**. One Undo step; ×, Esc or a click outside closes the card (a request still running carries on). Every prompt card closes on a click outside it (clicking Undo or Redo, or in the AI menu, keeps it open). The sound's right-click menu also has Play, Edit… and Delete….
- **Code editor** (right-click → Code): the object's behavior scripts as code, every copy's and this one's own, with line numbers; edit and **Save** (Ctrl+S), checked exactly like the AI's scripts (a mistake is named with where it is, nothing broken is stored); **Readable** shows a script in words; switch scripts on/off, remove them, or start a **New script**. **Components** shows its built-in behaviors (Patrol, Damage…) as code to read, and **Language reference** lists everything a script can use.
- **Export game…** (project menu) asks where the game is to be played. **itch.io (web game)** saves the game as a zip with `index.html` (the form itch.io takes HTML games in), and the dialog shows the steps to upload it there (Kind of project: HTML, "played in the browser", embed size, Draft then Public): people play it in the browser, with no download warnings. **Windows app** or **macOS app** gives a zip with the game as a program: unzip it and double-click (Windows 10/11: `<Game>.exe` with `game.html` beside it, using the Edge WebView2 that comes with Windows; macOS 11+: `<Game>.app` for Apple silicon and Intel). They aren't signed with a paid certificate, so the first time Windows says "Windows protected your PC" (players click *More info* → *Run anyway*) and macOS asks to allow it in *System Settings → Privacy & Security → Open Anyway*; a "How to play" note in the zip says so. Controllers and the keyboard work as in the browser. **Web page (HTML)**: the game as one web page that is only the game: it starts at once, with no start screen or hints (send it, or put it on a website; no editor, server or internet needed). **Download game player (HTML)** gives a page that plays any game dropped onto it (a saved .pxlproj.json, or an exported game page). Exporting asks whether to include **touch controls for phones** (on by default): on a touch screen the game then shows a D-pad and Jump/Fire/Use buttons (only the ones the game uses); on a computer they stay hidden. The game player page always has them. Play in the editor shows them too on a touch screen.
- **Open by dropping**: drop a saved game file (.pxlproj.json, or an exported game .html) from your computer onto the level to open it (Undo brings back the game you had).
- **Game name**: click the name at the top left and type a new one, or rename it in the Save window (Save asks for the name and saves the file under it).
- **PXLGameSite (the game shop)**: in the game's menu (on its name), **Save to PXLGameSite…** puts the game up for everyone using the app: its picture (the start of the first level as it plays, at the game's own pixels) with its name under it. **View PXLGameSite** shows everyone's games, newest first, with their picture, name and who made it: click one to play it right there (Esc goes back), or **Open a copy** to change it in the editor as your own. Your own games can be removed; saving a game again replaces it. The games are kept in the published app on claude.ai (its own database), so everyone the app is shared with can browse and play them, and people shared as Contributor (or more) can put games up. Outside claude.ai it says where to find it.
- **Save in one click**: the **Save** button next to the game's name (or `Ctrl+S`) writes the game's file. Opened as its own page in Chrome or Edge (https://gullibein.github.io/PXLBuilder/), it writes straight into the file: **Open…** (`Ctrl+O`) remembers the file you open, and the first Save asks once to allow changing it; after that every Save just writes it, with no dialog (a new game asks where to save the first time). The file is remembered after a reload too (the browser asks once again). Inside claude.ai the page is not allowed to write files itself, so each Save is offered as a download through claude.ai and the browser. Your work is also kept in the browser all the time (autosave). Saves made with the app on claude.ai earlier are still listed under **Open…**.
- **Saving over the same file**: in Chrome and Edge (the app opened on its own page, e.g. on your computer or GitHub Pages), the first Save asks where to put the file, and later Saves write over that file (the Save window says which; **Save as new file…** picks another). Elsewhere, and in the published claude.ai app, Save is a download, and the browser numbers a file whose name is taken ("game (1).pxlproj.json"); to replace the old file instead, turn on your browser's "Ask where to save each file before downloading" (Chrome: Settings → Downloads) and pick the old file.
- **Leave out objects no level uses** (Save window): the file then has only the objects placed in some level and those they use (a script that creates copies of an object keeps it), and the pictures they show; sounds always stay. Only the file: the editor keeps them all, and **Reset objects to defaults** brings back built-in objects to a game opened from such a file. The window lists what would be left out; the choice is remembered.
- **Export sprites**: project menu → **Export sprites…** saves the game's pictures as one sprite sheet: **Save PNG** (pixel-sharp, at 1×, 2×, 4× or 8×) and **Save JSON** (the usual atlas format game engines read: each picture, sprite-sheet cell and animation frame by name with its rectangle on the PNG, animations as lists of frames with their speed, and the pixel-art pictures as data: palette and rows). By default only the pictures the game uses. In the sprite editor, **Export…** does the same for the sprite you're drawing (all its frames).
- **Sprite size**: every built-in object comes with ready-made pictures at 8×8, 16×16, 32×32 (as they ship) and 64×64 pixels a tile (odd-sized objects in proportion: the spikes are 16×8 at 16). Pick it when starting a game, change it in the project menu (Sprite size), or ask "make the sprites 8x8 pixels" (done by the app at once, no AI needed). Objects with your own drawings keep them; new drawings (sprite editor, AI) use the game's size: the AI's drawings are checked, and one with more pixels than the game's size allows (a 16×16 picture for a tile in an 8×8 game, also for objects it makes in the same answer) is sent back to be drawn again at the right size. The 8×8 pictures are their own hand-drawn set (new designs in one 16-color palette, the top-down hero's walk cycles included); the 64×64 ones are made from the 16-pixel drawings with Scale2x (a pixel-art upscaler). A game already on 8×8 gets the new set by picking 8 again.
- **Heart** (built-in object, Items): picking it up gives back one heart of health (Collectible **heal**, up to the most the player can have). Its picture is also the picture of the player's hearts at the top of the screen in Play (empty hearts greyed), so redrawing it (sprite editor, or "make the hearts blue") changes them too. Hand-drawn at 8×8, 16×16 and 32×32; 64×64 is made from the 32×32. Games saved before it get one when opened.
- **Winning a level**: touching the goal (in a top-down game: standing on it, the player's middle on the goal or exit, not just brushing its edge) freezes the game (nothing moves, the player can't be steered on) while "Level complete!" shows; then the next level starts.
- **Camera outline**: shown on the level once anything is placed (with nothing to follow, it shows where the still camera looks).
- **Several levels at once**: ask "make me a Lode Runner clone with three levels" or "add two more levels". The AI makes the new levels (after the ones you have, played in that order), each with its own player, layout and goal, all in one answer (one Undo takes them all back); each gets a different layout idea from the app. New levels play like the game's others (a top-down game's new level is top-down too). Pick them from the level menu at the top.
- **Generate or redraw levels**: double-click empty space and describe it: "Generate a hard level with spikes, enemies and teleporters". The AI uses your objects (or makes simple ones it needs), keeps jumps within the player's reach, and builds it right away: look around, play it, and Undo if you don't like it. Every AI change works this way (no Apply button); a change to an object (every Enemy) can be turned into a new object with one click on the card.
- **Prompt cards are chats**: each thing you talk to (an object, a pair, the level, the background…) has its own conversation with the AI, shown on its card with the field below it, so you can answer the AI's questions or follow up. Closing the card, selecting something else or reloading the page keeps it, and the AI remembers it; **New chat** on the card starts a fresh one (AI History keeps the old one).
- **Camera outlines**: the level shows what Play shows when it starts (white) and where the camera may not look past (red). The **camera tool** on the left toolbar (and ⋯ → Camera outlines) shows or hides them. Hover one to highlight it; click it (its line, or its label, which works even where objects are under the line) to open its AI card (the camera's own conversation, apart from the level's): ask about the camera ("zoom out a bit", "no limits"), or press **Settings** on the card for the **Camera** settings: **Follows** (any object placed in the level, or nothing for a still camera; the others stop being followed, in this level only), **Ease** (how softly it catches up: low = slow and soft, 1 = sticks to it), **Zoom**, **Look ahead** and **Dead zone** (when it follows something), **Looks at** (where a still camera points), **Limits**, and the game's **Resolution** (how many picture pixels the screen shows top to bottom when played, in Play and in exported games: 180 zooms in so the screen is 180 game pixels tall, every pixel of every picture shown whole and the same size; the camera's zoom then counts in whole picture pixels, 2 showing half as much; not set = as big as the screen). Every change is one Undo step. ⋯ → Camera outlines hides them.
- **Even pixels in Play**: the camera and everything on screen move in whole screen pixels (at a low game Resolution: whole game pixels, as on a real low-resolution screen), and a picture keeps exactly its size wherever it is; pictures are always drawn with all their pixels the same size: Play rounds the camera's zoom a little to the nearest size where each picture pixel is a whole number of screen pixels (on a screen scaled to 125%, 32×32 pictures are drawn one screen pixel per picture pixel), and the editor's low-resolution Play (a speed setting, ⋯ menu) never draws them with fewer pixels than they have.
- **A light editor**: the level is drawn once into a layer of its own and drawn again only when it changes (the game, the view, a drag); moving the mouse only redraws the hover frame and other marks on top, and an idle editor with nothing moving draws nothing. `node scripts/profile-editor.mjs <game.pxlproj.json> [slowdown]` measures it on a slowed-down CPU.
- **Low-resolution play** (on by default, a speed setting for this browser): Play draws the game with fewer canvas pixels (about 400 tall) when the pictures have fewer pixels than the screen (8×8 pictures, or a zoomed-in camera), scaled up with hard edges, which is much lighter work for weak graphics chips; never fewer than the pictures have. To make a game itself low-resolution (zoomed in, chunky pixels, also in exports), set its **Resolution** in the camera's Settings. ⋯ → Low-resolution play (faster) switches to full sharpness; the Editor prompt can set any height ("play resolution 300").
- **Levels stay in view**: switching to a level shows it as you left it, or frames it whole the first time; what the AI builds off screen is brought into view.
- **Sounds**: ask for any sound and when it plays: "the duck quacks when the player touches it", "a springy boing when the player jumps on the spring", "an explosion when the bomb goes off". The AI writes the sound as up to 32 notes (like PICO-8's sound effects) and makes the game play it; the card has ▶ to hear it and ✎ to edit it. **Sounds** tab (bottom bar, next to Objects): every sound on one line, to play (▶), edit (✎) or delete (trash, after a "Delete sound?" dialog); **+ New sound**; and an AI prompt at the bottom: describe a new sound ("a springy boing when the player jumps": it makes the sound, and makes the game play it when you say when), or a change to one by name. The **sound editor** has a **✦** next to the trash: it opens an AI prompt card about the open sound ("lower in pitch", "more like a laser"), or for a new one when none is open; × or a click outside closes it. The Objects and Sounds tabs close with the × at their top right, or as soon as the top bar, the tool bar or the AI History / Console / Debug buttons are used. **Sound editor** (the ♪ at the top, next to ✦, opens it on the sound last edited (with none, it is greyed out until + New); **+ New sound** there, in its menu or in the Sounds tab makes a new one; the menu at its top switches to another sound): drag in the top part to draw each note's pitch with the chosen **wave** (triangle, tilted saw, saw, square, pulse, organ, noise, phaser), the middle strip sets each note's **volume** (0–7), the bottom row its **effect** (slide, vibrato, drop, fade in, fade out); right-click (or Alt) in the note area deletes notes outright; right-click in the volume strip only turns a note off (it keeps its pitch and wave, shown as a faint outline: give it a volume to hear it again); **+ New** next to the name makes another sound, and the 🗑 next to it deletes this one (a "Delete sound?" dialog asks first; the editor stays open with no sound in it, greyed out until + New or the menu opens one; Undo brings it back); **double-click** a wave, volume or effect (or right-click it → **All notes**) to put it on every note that sounds; **Smooth** (0–7) softens the whole sound (noise becomes a whoosh or rumble instead of a hiss); **Speed** sets how long each note lasts; Space or ▶ plays it; rename it at the top (scripts that play it follow the new name). Every stroke is one undo step. Ask the AI to change a sound you edited ("make the quack lower") and it starts from your notes. Sounds made before the editor still play (ask the AI to remake one to edit it). Short effects and jingles; for music, see the music machine.
- **Music machine** (the **Music** button in the bottom bar): shape instruments and write songs, saved with the game. **Instruments** tab: pick the **8-bit** chip (NES / Game Boy: square and pulse waves, a stepped triangle, noise and metal noise, the volume moving in steps) or the **16-bit** chip (SNES / Mega Drive: saw, square, triangle, sine, FM, pluck, supersaw, noise, plus a resonant filter and echo); shape the volume (attack, decay, sustain, release), the pitch (a slide in, e.g. a kick drum; vibrato; an arpeggio such as `0 4 7`, a chord on one channel the chiptune way), the filter (cutoff, resonance, sweep), FM ratio and brightness, supersaw detune, echo time, repeats and mix; the picture shows the sound over time. Try it on the keyboard with the mouse or the computer's keys, by where they are, so any keyboard layout works (Icelandic too): the bottom letter row and the row above it are the lower octave, the top letter row and the number row the upper one, and each piano key shows the key that plays it (in Chrome and Edge, as printed on your own keyboard); ← → change the octave. **+ New instrument…** starts from a ready one (square lead, triangle bass, chip kick, snare and hi-hat, saw lead, FM bass, FM bell, electric piano, pluck, string pad…); **Start over from…** reshapes one from a ready one. **Songs** tab: **+ 8-bit song** / **+ 16-bit song** start a song with three instrument channels (a lead, a second voice, a bass) and, below a line, three drum channels (kick, snare, hi-hat); **+ Channel** under the instruments and **+ Drum channel** under the drums add more (up to 12 in all; each channel plays one instrument, with a volume, mute (M) and ✎ to shape its instrument). In the song, your computer's keys (and the keys at the roll's left edge) play the chosen channel's instrument, with its own octave (◀ ▶ or ← →). On any keyboard, hold the mouse button (or a finger) and slide along the keys: each key reached plays and the one left fades out as its instrument's release says. Click the piano roll to add a note on the chosen channel (drag right to make it longer; drag either end of a note, either way, to make it longer or shorter; *Note length* sets how long a click makes it), click a note to take it away; the other channels' notes show faintly. A song is **patterns** (A, B, C…; **+ New**, **Copy**, **Clear**, **Delete**) played in an **order** (+ adds the pattern after the chosen place, − takes it out, ◀ ▶ move it), at a **BPM**, with a number of **steps** per pattern (16 = one bar of 16th notes), looping or played once. **▶ Song** (or **Space**, which also stops it) plays from the chosen place in the order, **▶ Pattern** plays the pattern over and over; changes are heard while it plays. **Music of level "…"** makes the song play while that level is played (in the editor's Play and in exported games); scripts can change it (*play_music* "Boss theme", *stop_music*). Double-click a name (or ✎) to rename it (scripts that play the song follow), 🗑 deletes it. Every change is one Undo step. The **✦** in the music machine's top bar (next to the tabs) opens an **AI prompt card** about the open tab (× or a click outside closes it). In **Songs**, describe a whole song ("a spooky castle theme in a slow waltz"), a melody ("a rising, hopeful tune that ends high"), a feel ("make it more aggressive"), or just one part ("make the drum beat busier", "a new bass line"): the AI changes only what you asked about and leaves every other note as it was, or writes a new song when there is none (it opens in the tab). In **Instruments**, describe a sound ("a fat wobbly bass", "a soft flute", "make it brighter and punchier"): the AI can set every knob, button and slider (chip, wave, envelope, pitch slide, vibrato, arpeggio, filter, FM, detune, echo), and the sliders move to show what it did. Elsewhere, ask the AI too: "write a cheerful 8-bit theme for this level", "make a spooky 16-bit song for the castle and play it when the boss appears": it makes the instruments, writes the song and sets it as the level's music, and you can open it in the music machine to change it.
- **Fast scripts in big levels**: scripts' questions about places and things (`thing_at`, `solid_at`, `player`, things by tag) and touch checks use an index of the level by grid cell instead of looking at every thing, so a Boulder Dash level with hundreds of boulders, dirt and walls runs about three times faster, with exactly the same results.
- **One pixel size for everything**: everything you see in play is part of the game and keeps to its pixels. The player's hearts are the game's Heart object, drawn into the game the size it is in the level (an 8×8 heart is 8 game pixels); item counts, messages and "Level complete!" are in the pixel font on the same pixels; what scripts draw on the screen is snapped to them too (pictures a whole number of game pixels per picture pixel, boxes and circles in whole pixels, and in a game with its own resolution all text in the pixel font). (Only the editor's own key hints and the touch-screen buttons are not part of the game.)
- **Color picker**: the Background card's own color and the sprite editor's colors (**+** to add one, **This color** to change one) open PXLBuilder's color picker: a color square and a hue bar, the old and new color side by side, the color as hex and as R, G, B, an eyedropper (where the browser has one), and **OK** / **Cancel** (or Esc): nothing changes until OK. The Background card's picture has **Download** (as the game shows it, at its own pixels).
- **Generated backgrounds**: the Background card's **Image generator** makes a background picture from a description ("a starry night over mountains") with PXLBuilder's own image generator (a Cloudflare Worker that takes `POST {"prompt": "…"}` and answers with the picture), so it works out of the box; **settings** can point it at another one (kept in your browser; **Default** goes back). **Size**: **Level** (the camera limits box), **Screen** (what the camera shows: in a game with its own resolution exactly that many game pixels tall) or **User defined** (width × height in game pixels); a dashed box in the level shows where the new picture goes and how big it is, as it is chosen. The picture is made at exactly that size, its middle cut to that shape, in at most 32 of its own colors, and placed in the level in that box (**Fit: Placed**), moving with the level. **Click the picture in the level** (where no object is) to select it: its box with handles, and an AI **✦** above it for the background's prompt card (the same conversation as the Background card's; its **Settings** opens the Background card); a picture that fills the screen or repeats is selected inside the camera's start outline (no handles: it isn't placed). Esc, or a click outside it, lets go. While it is selected or the card is open, its box shows in the level: drag inside it (where no object is) to move it, its corners to resize it keeping its shape (Shift: any shape), its sides to stretch it; at a new size it is drawn again from the original, so each picture pixel is still one game pixel (one Undo step per drag). Any background picture can be **Placed** (or **Fill** the screen's height, or **Repeat**). **Movement**, separately for the camera going **left / right** and **up / down**: moves with the level, moves slower (far away: then a slider says how much), or stays on the screen (e.g. stays on the screen sideways but moves with the level up and down; ask the AI the same in words). Fill always fills the screen's height, so it only has left / right. A placed picture is exactly where it was put when the level starts, whatever its movement (Screen-sized pictures are made to stay on the screen: the usual background). In the editor, a picture that fills the screen or repeats is shown inside the camera's start outline, as Play shows it then. Inside claude.ai the page may not be allowed to contact other sites: make the picture in PXLBuilder at gullibein.github.io/PXLBuilder; it is kept in the game file.
- **Rounded tile corners**: an object's Sprite has **roundCorners** (for anything laid out in a grid, also objects the AI made that aren't marked as tiles; 0–8 picture pixels; or ask the AI "round the corners of the dirt"). The engine rounds the outside corners of the surface the tiles make and fills the inside corners where a tunnel or gap turns, from the tiles around, also as tiles are dug away in play (Boulder Dash, Dig Dug). No script needed, and it costs nothing extra while playing.
- **Everything can change while playing**: scripts the AI writes can read and change any property of anything during play (size, scale, rotation, colors, sprite, jump force, speed, health, collisions…), add or remove abilities (climbable, stompable, harmful…), and draw their own display on the screen (big hearts, a score, a timer, a health bar over a boss), hiding the built-in hearts or items. In a game with a low Resolution (128 pixels tall, PICO-8 style), small text is drawn in a compact 3×5 pixel font on whole game pixels, so it stays readable instead of blurring, and bars and boxes keep sharp edges. Ask in plain words: "the player grows when it eats a mushroom", "make the hearts bigger", "show a timer". Turned walls and platforms collide as the upright box around them; characters keep an upright box while drawn turned.
- **Hidden or invisible**: an object that *starts hidden* is out of play (it can't be touched, climbed or collected) until a rule or switch shows it, e.g. a ladder that appears after the last coin. An object whose sprite is set to *not visible* is still there and works (a secret ladder or platform), it just isn't drawn in play; the editor shows it faintly so you can find it. Things that start hidden are shown half see-through in the editor. Ask for either in words.
- **Ways to win**: drop a *Goal* (flag) in a level: touching it finishes the level, and Play moves on to the next level. Or describe it: "the level is won when all coins are collected", "after the last coin a ladder appears that climbs out of the screen". The AI varies where levels start, which way they go and how they're won. *Teleporter* pads ship as built-in objects: wire two together ("this teleporter sends the player to that one").
- **The editor itself**: the ✦ prompt's **Editor** tab. "Move the Play button to the bottom", "dock the details panel on the right", "make the editor green", "zoom slower with my mouse". Editor changes are saved in your browser (not in the game) and have their own Undo; ⋯ → **Reset editor layout** puts everything back.
- **Create**: the bottom dock's **+ Create** makes a new object from a description.
- **Tools** (left panel): the arrow selects and moves (`V`), the pen draws (`B`), and the picture button opens the level background.
- **Draw**: pick an object in **Objects** (e.g. *Platform* or *Ladder*) and click or drag on the level to place it, one per grid cell; then it's back to the arrow, with the last one placed selected (drag its box's side points to make the line longer). To keep drawing stroke after stroke, press the pen (`B`) first: it draws with the last object used, and objects picked in **Objects** while it's on keep drawing too. The editor starts with the arrow. Shift keeps a stroke straight, right-drag erases; Esc or the arrow stops drawing. Each stroke is one undo step. You can also drag objects in directly.
- **Objects** (bottom bar): a compact menu above the bottom bar. Clicking an object picks it to draw with (the menu closes).
- **The object's card**: whenever an object is picked in the Objects menu or selected in the level, a small card at the top right shows its picture and name, with **Edit sprite**, **Autotile…** (for grid objects) under it and **Details…** under that. Details… opens the full details, docked at the right edge of the screen (narrow, full height), in the card's place: a placed object's own, or a picked object's; they too start with its picture and Edit sprite. × closes the card until something else is selected or picked. While the details are open, the AI History / Console / Debug buttons sit to their left as icons.
- **Autotiling**: for objects laid out in a grid (platforms, ground, walls): the object's card → **Autotile…** (or Details, or right-click the object → **Autotile…**) opens the Autotile editor. **Make the 16 pictures** makes one picture for each combination of neighbours (a tile of the same object above, right, below, left), from the object's picture or its color, in a style: open sides with a **darker edge** or as the tile, the open top **lighter**, **grass** or as the sides, outside corners **rounded** or not. Then each tile in the level (and in play, also as tiles are dug away) is drawn with the picture that fits the tiles around it: a platform gets ends, a block of ground edges and corners. The 4 × 4 overview shows the 16 (marks show which sides are joined); click one to draw it by hand in the sprite editor (always 16 pictures there, not an animation). **Try it**: a small level to add and remove tiles on. The **Autotile** switch turns it off and on again (the pictures are kept). One Undo step each. **Edit the top edge** / **Edit the bottom edge**: draw the top (or bottom) once, as a strip of rows, and it goes on all 8 pictures with that side open (nothing above, or below); the ends keep their rounded corners and darker sides, the pictures with a tile there stay as they are. The pictures and the little level show it as you draw; choose how many rows, pick or add colors (left button draws, right erases); **Apply to the 8 pictures** (one Undo step) or Cancel. **Ask the AI** (in the editor): ask for a kind of tile ("stone bricks", "ice", "a grassy dirt platform") or a change to the tiles there are ("moss on the top edges", "rounder corners", "darker outline"): the AI is given the 16 pictures (which sides each joins) and redraws all of them or just the ones that change, at the tiles' pixel size; one Undo step, its own conversation. Asked anywhere else ("make the platforms autotile as stone bricks"), it can draw them too.
- **Sprites**: right-click an object in **Objects** → **Sprites**. Import a single image, or a sprite sheet: the grid is detected and every cell is numbered; adjust the grid if needed and click a cell to use it. Sprites stretch to the object's size. **Plain box** draws the object as a box of one color instead of a picture (pick the color with **Box color**); the picture stays in the list to choose again. Right-click → **Details…** shows all its properties.
- **Size link**: in the Inspector, sprite and collider sizes are linked (changing one changes the other). Click **Linked** to size them separately.
- **Background**: choose a color, upload an image (Fill or Repeat, and how much it moves with the level), or describe what you want ("the background should move sideways along with the level").
- **Dying and respawning**: a player that loses its last heart stays where it died for its *respawn delay* (Health → respawn delay; the starter Player: 1 s), with no controls and nothing hurting it, while a death animation plays (ask: "when the player dies, it hops up a little and fades out"). Then it comes back at its start, standing still, with full health: keys still held from before are ignored until let go, and its scripts start over in their first state (their numbers, like lives and score, are kept), so a death animation never plays again after the respawn. A script can make a character die (Sonic's ring loss, a time limit): the *kill* statement (even while it blinks after a hit), or its health set to 0, is a real death with all of the above.
- **Enemies**: the built-in Enemy patrols about 4 tiles each way from where it starts, now and then climbing a ladder it passes (up or down), and chases the player once it sees it (within 8 tiles, nothing in between), by ladder too; it goes back to patrolling after losing sight of the player for 3 seconds. While chasing it runs a little faster, stops at walls and ledges, and when the player jumps over it, it slows down for 0.3 s before turning (its *reaction*), so a quick player can get away. Jump on it to defeat it (Stompable). Enemies line up with a ladder's middle before climbing, so the floor beside a ladder can't stop them. Tune it in its details (Patrol: distance, climb ladders, chase range, chase speed, reaction) or ask ("enemies hunt the player across the whole level"). Scripts can climb too (the *climb* statement).
- **Play**: the ▶ Play button (or `Ctrl+Enter`). Arrows/WASD run, Space jumps (one row up), Up/Down climb ladders (you ease to the ladder's middle unless you also press Left/Right; you stop on the top; a ladder above a gap needs a jump), `E` uses a switch, `R` restarts, `Esc` stops. **Game controllers** (Xbox, PlayStation, Switch Pro, Steam Deck… plugged in or paired) work too, in Play and in exported games: d-pad or left stick moves, the bottom button (A / Cross) jumps, the right and top buttons (B / Circle, Y / Triangle) use, the left button (X / Square) or the right trigger fires, Select/Back restarts. Games and their scripts need no change: a controller gives the same actions as the keys (press any button once if the browser doesn't notice it at first). The player picks up coins and keys, loses a heart touching hazards and enemies, and starts over when out of hearts; the top-left shows hearts and items. Playing never changes your level.
- **Falling-block puzzles (Tetris and the like)**: scripts can move groups of things as one piece. *spawn* can tag what it makes ("active"), *fits(tag, dx, dy, block)* / *fits_turned(tag, x, y, dir, block)* check that the whole group would fit (no wall, nothing with the block tag), *move_group* / *turn_group* move it or turn it a quarter around a point, and *count_in(tag, x1, y1, x2, y2)* counts what is in an area (a full row). The AI knows the recipe (a well, a Block object and one Board script: the seven pieces, moving, turning, dropping, locking, clearing rows), so "make a Tetris clone" builds one.
- **The level, compactly, for the AI**: each prompt sends the level as a text map with one character per object (the legend names each object; the most common solid stays "#", others get a letter, e.g. "d" for Dirt), plus where the player can walk and stand. Only the few of a kind (the player, doors, a goal) and copies changed on their own are listed one by one; plain copies of things placed many times (ground, walls, dirt) are only on the map. A whole-game prompt shows the other levels as maps too. The object list is short too: each object's name, kind, tags, components, size and its scripts' names with the first sentence of their descriptions (the selected thing's code comes once, in full, with the selection). On a Boulder Dash game prompts went from 61,000-124,000 characters to 12,000-18,000. Cells where two objects overlap are pointed out to the AI.
- **The AI reads other objects' code when it needs it**: each prompt sends the selected object's code in full and only the names and one-line descriptions of the other objects' scripts. When the AI needs another object's code (why does the diamond fall through?), it asks for it and the app sends it at once (the console says so); that second request reads the game's data from the cache. One prompt, so it is one Undo and one card answer as usual.
- **What the AI costs with your own Anthropic key**: ⋯ → AI connection has a **Model** choice: *Opus 5.5* (the default; $4 / $20 per million tokens in / out), *Sonnet 5.5* (half that) or *Haiku 5.5* (about 40× cheaper than Opus; fine for small changes, more likely to get scripts and whole levels wrong). After every request the console says what it cost, worked out from the token counts Anthropic reports (e.g. "AI request: $0.054 (claude-opus-5-5: 26,000 tokens in (25,000 from cache) · 2,000 out)"), and AI connection shows the totals for the session and for this browser. The fixed instructions (about 25,000 tokens) are cached for an hour and the game's data for each request, so pauses between prompts and answers sent back to be fixed cost much less. Your Anthropic Console has the exact bill. The AI is sent the full code of the objects a request names, so it rarely needs to ask for code first; a null it writes for a script setting means that setting's default. Claude's answers are streamed, with room for up to 64,000 tokens (a whole game with drawings for every object fits; you only pay for what it writes). Claude answers in a strict reply format (Anthropic checks the answer's shape as it is written). A model whose limits are too small for the full format (Sonnet 5.5 allows fewer "null or a value" fields) gets a compact form of the same format instead, which the app reads back into the full one; only if that is refused too does it answer through a reply tool. The console says which happened, once per visit. Opus keeps the full format.
- **Choosing the AI per request**: every AI prompt field, the New game field included, has the AI button (left of Send / Make it): pick Opus, Sonnet or Haiku (or Gemini) there; the choice stays until you change it.
- **AI connection** (⋯ → AI connection): choose **Speed**, *Best quality* or *Fast* (Claude thinks less; on claude.ai its quicker model): much quicker, a bit more likely to get hard requests wrong. Outside claude.ai (on your computer, or the GitHub Pages site) you can also choose **Google Gemini** (e.g. Gemini Flash) with your own Gemini API key from aistudio.google.com: the key stays in your browser and is sent only to Google; pick the model (Gemini 3.8, 3.7, 3.6 and 3.5 Flash and 3.5 Flash-Lite are always offered, plus whatever else your key can use) and a backup for when it's busy (default 3.5 Flash): a busy model's request goes to the backup automatically, and the backup keeps answering for a couple of minutes; the console says when. Gemini can't be used in the published claude.ai app (pages there can't contact other services).
- **Debug**: the bottom-right **Debug** button lists what can't work in the level as it is set up (a door that needs a key nothing gives, damage nothing takes, a "switch" that isn't one, a script line that changes nothing, a script that steps the player square by square while its Character Controller still walks it too, solid objects stacked on the same square such as dirt hidden under a wall); **✦ Fix** asks the AI to fix one (you see the fix before applying it). After you play, it also shows what happened (deaths, falls, locked doors, script problems) with questions to ask: "Why did the player die?", "Why didn't Door open?". You can ask any prompt "why…?": the AI gets the last play and the problems with every request.
- **One conversation per object**: every placed copy of a library object is that object, so the AI conversation about it is the same on every copy's prompt card and on its card in Objects (right-click → Ask AI…), and the AI remembers it wherever you ask. A selection of several things, a connection or the level have their own.
- **Deleting a library object**: Objects → right-click it → **Delete…** asks first; when it has copies in the levels, **Delete it and its copies**, or **Keep the copies** (they stay as standalone things). Undo brings it back.
- **AI prompt card on request**: clicking selects (an object, a group, a connection, a camera outline) without opening anything; an AI **✦** appears above the selection, and clicking or tapping it opens the AI prompt card. Double-clicking (or double-tapping) an object or empty level opens it directly (empty level: the level's card), as do **Enter** with something selected and **Ask AI…** in the right-click menu. A click elsewhere closes it.
- **Prompts go to the card of what they changed**: asked on one thing's card (the Player's), an answer that changes only one other thing ("make the enemy faster") is moved to that thing's card: the conversation and its Undo are there, as if asked there. The card it was asked on says so ("This changed the Enemy, not the Player, so it was moved to the Enemy's prompt card") with **Go to the Enemy's card**. An object placed once: that one's card in the level; placed several times (every copy changed): the object's card in **Objects** (its Ask AI… card). Answers that change the thing asked about, several things, or the level stay where they were asked.
- **Right-click menu on touch screens**: a long press (half a second, finger still) opens it.
- **Details**: right-click an object → **Details…** (or press `I`) opens the full property drawer for advanced editing; right-click empty level → **Details…** for the level's settings (gravity, background…).
- **AI selector** (the chip button next to each prompt, showing the AI that answers: Opus, Haiku, 3.8 Flash…): pick the AI right there. With your Anthropic key: Claude Opus 5.5, Sonnet 5.5 or Haiku 5.5 (with prices). With a Gemini key: the Gemini models that key can use (Google's list for it: the Flash models, Flash-Lite, Pro…). On claude.ai: your account's default or quicker model. Also Best quality / Fast, and **AI connection…** for keys.
- **Undo/Redo**: top bar, `Ctrl+Z` / `Ctrl+Shift+Z`. AI changes are single steps. **Console** (bottom right) has **Copy**: the whole console as text, with the app's version, to paste into a message when something goes wrong. **AI History** (bottom right) shows your conversation with the AI in full: each request, what it was about, the AI's whole answer, its changes and how it ended (applied, undone, an answer, a failure), kept in this browser and **saved in the game file** (Save; opening the file brings it back; it is for you to read and is never sent to the AI; an exported HTML game doesn't contain it). An AI change you undo (toolbar, `Ctrl+Z` or its card) shows **↶ Undone** on its card and here, and stays marked after later edits; Redo marks it applied again; tick **My edits too** to see your own changes alongside, and use the corner button to make the panel bigger. **Details (under the hood)** on an exchange shows what happened: which AI answered, how much was sent, the AI's raw answer, the app's checks and retries; **Download** saves the recent exchanges with these details as a file (no API keys in it) to share when something goes wrong.
- **Box select (M)** in the tool bar: a drag always draws a selection box, even one starting on an object (Shift adds to the selection); a click selects one object. With the arrow (V), a drag on empty space box-selects too, and a drag on an object moves it.
- **Eyedropper (E, or hold Alt)** in the tool bar: click an object on the level to pick up its kind, as if picked in the Objects panel; then click to place one or drag to draw a line of them (afterwards the editor is back to selecting). Holding Alt gives the eyedropper whatever the tool; let go and you're drawing with what you picked.
- **Game text in Play** ("Level complete!", messages) is in a console-style pixel font (Press Start 2P, built in, so exported games need no internet for it).
- **Erasing while drawing**: with the pen (or an object picked to draw), the **right button** erases whatever is under it, whatever you're drawing with; a floor drawn under everything goes only once nothing else is left on it.
- **Placing over objects replaces them**: an object dropped, drawn (pen, eyedropper) or stretched (a row or ladder with the selection box's side points) onto squares where other objects are deletes those and takes their place, in the same Undo step (the console says what was replaced). Check **Add on top** in the tool bar (or in the editor settings) to keep them and put the new ones on top. Floors (objects drawn under everything) are never replaced.
- **Selection box**: fits the selection exactly (a 32×32 tile gets a 32×32 box). Drag a **round point on a side** to repeat what is along that side, one object at a time (floors, walls, ladders: shown faintly while you drag). With a row selected, its right point adds one tile at a time to the end, its top point adds one row at a time on top; so a line becomes a block row by row. Drag a side point **inward** to make it shorter from that side (a ladder from its top, a floor from its end), one object at a time; what will go shows faintly until you let go, and the last one always stays. Drag a **square corner point** to resize one object (the opposite corner stays; on the grid while snapping). Each drag is one Undo. Works with a finger too. While you move, stretch or resize objects, their prompt card steps aside (it's back when you let go).
- **Move**: drag objects (tiles snap to whole tiles); arrows nudge; `Ctrl+D` duplicate; `Ctrl+C` / `Ctrl+X` / `Ctrl+V` copy, cut and paste (also into another level); `Del` delete.
- **Typed commands, no AI needed**: in an object's (or the level's) prompt card, plain editing words are done by the app itself, at once, with or without an AI connected: *delete* (erase, remove), *duplicate* ("duplicate 3 times to the right"), *copy*, *cut*, *paste*, *move left/right/up/down* ("move up 3"), *rename to …*, *select all* ("select all coins"), *deselect*, *undo*, *redo*; *help* lists them. On a connection, *delete* removes it. Anything more ("delete the spikes and make the door red") goes to the AI.
- **View**: trackpad two-finger scroll pans, pinch or Alt+scroll zooms. Mouse: wheel zooms, Shift+wheel scrolls sideways, middle-button drag pans. Space+drag pans with either. `F` frames everything. **Zoom bar** (bottom left): − and + zoom one step, the slider from 10% to 800%, a click on the percentage goes back to 100%. A mouse wheel zooms one moderate step per notch (also when the browser or app reports it as Ctrl+wheel, which used to jump almost three times as far).
- **Project** (click the project name in the top bar): **New project** (an empty level with the built-in objects as they ship), **Open…**, **Save** (downloads a `.pxlproj.json`, kept small: a placed object stores only what differs from its object, and pixel-art pictures and sounds are stored once, as their pixels and notes; files saved by earlier versions still open; the project also autosaves in your browser), and **Reset objects to defaults** (built-in objects go back to how they ship; your level and your own objects stay; undoable). Right-click a built-in object in **Objects** → **Reset to default** for just that one.
